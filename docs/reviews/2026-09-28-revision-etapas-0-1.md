# Revisión de código de las Etapas 0 y 1 (2026-09-28)

Rangos revisados: back `f03fe6e..e1b2ff0`, front `81d1ee4..5060c99`. Cuatro revisiones independientes; los hallazgos altos se verificaron en el código. Cada punto: dónde, qué pasa y la corrección. Todo va con TDD: primero un test que falle, después el arreglo, y si una ficha decía algo distinto se corrige la ficha en el mismo commit.

## A. Prioridad alta (bugs reales o controles que no controlan)

1. **Zona por defecto de cada país mal generada.** `scripts/datos-de-referencia/generar.mjs:397-402` toma la primera fila de `zone1970.tab` (DE → Europe/Zurich, UA → Europe/Simferopol, BR → America/Noronha, AU → Australia/Lord_Howe, CA → America/St_Johns, RU → Europe/Kaliningrad). Corrección: país con una sola zona → esa; si no, la principal de `cldr-core/supplemental/primaryZones.json` (mapeando el ID CLDR a IANA); si no hay principal (US, CA, AU, BR, RU, MX, ID…), `null` salvo override en `habilitados.json`. Test: DE → Europe/Berlin, UA → Europe/Kyiv, AR → America/Argentina/Buenos_Aires.
2. **Ciudades de zonas sin traducir por alias de CLDR.** `generar.mjs:237` busca `exemplarCity` con el ID IANA y CLDR usa el histórico (Asia/Calcutta, Europe/Kiev, Asia/Saigon, Asia/Katmandu, Atlantic/Faeroe, America/Cordoba…). Corrección: fijar `cldr-bcp47@48.2.0`, resolver alias con `bcp47/timezone.json` y buscar con cada alias; quitar el override manual de Córdoba. Test: Asia/Kolkata → "Calcuta" (es).
3. **CI no corre el generador.** `.github/workflows/ci.yml` no tiene Node: `generar.test.mjs` (salidas byte a byte) nunca corre. Agregar `actions/setup-node` con `scripts/datos-de-referencia/.node-version` y `npm ci && npm test` en esa carpeta. Además, los nombres de cultura salen del ICU de Node (`generar.mjs:247-248,316-317`): tomarlos de `cldr-localenames-full` (languages/territories) para no depender del ICU instalado.
4. **`NoManualFormattingTests` tiene un agujero.** `tests/.../ArchitectureTests/NoManualFormattingTests.cs:71-89` solo detecta `ToString(string…)`. Sumar `DefaultInterpolatedStringHandler.AppendFormatted` con formato (`$"{x:N2}"`), `string.Format`, `StringBuilder.AppendFormat`, `ToString(IFormatProvider)` y `ToString()` sobre numéricos y fechas, con lista blanca de dueños técnicos (conversores de wire), y sondas negativas de cada forma.
5. **`HarnessTests` no ve tests `.test.mjs`/`.test.ts` ni exige que una clase `*Tests` tenga `[Fact]`/`[Theory]`** (`HarnessTests.cs:93, 448-453`). Reconocer los tres tipos (y el repo hermano si está) y exigir al menos un test por clase.
6. **Idempotencia en el front: la clave no se renueva después de un 4xx** (`src/shared/api/useIdempotentMutation.ts:23,29-31`). El back guarda también los 4xx, así que reenviar corregido da 422 `Request.IdempotencyKeyReused` y el formulario queda trabado. Corrección: renovar la clave después de cualquier 4xx salvo `Request.InProgress`; conservarla solo ante red o 5xx; tope al bucle de `Request.InProgress` (por ejemplo, 30) y cortar si se desmonta. Corregir idempotencia.md (back) y datos-y-api.md (front), que decían "solo tras éxito".
7. **Los campos no avisan cuando el texto queda inválido** (`MoneyField`, `NumberField`, `PercentField`, `DateField`, `DateTimeField`, `TimeField`, líneas ~30-51): el padre conserva el último valor válido. Corrección: ante texto inválido, `onChange(null)` + `onValidityChange(false)` (como PhoneField y TaxIdField); error visible recién al salir del campo. Corregir `MoneyField.test.tsx:127`, que fijaba el defecto.
